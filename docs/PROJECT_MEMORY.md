# Casa Paraiso Project Memory

> Last reviewed: 2026-10-07
> Role: orientation and routing; verify current source before changing behavior.

## Current Shape

Casa Paraiso is a Laravel 12 server-rendered web application using MariaDB 10.11 LTS. It supports customer, receptionist, therapist, administrator, and super-administrator workspaces. Core modules are services, staff and customers, weekly availability, calendar appointments, transactions, attendance, commissions, feedback and sentiment, RFM rewards, settings, reports, and CSV export.

Earlier native-client, versioned API, device-token, database, tunnel, and hosted-pilot integrations are retired. The previous repository and database infrastructure remain archival rollback sources only.

## Entry Points

- `routes/web.php` and `routes/auth.php` own all HTTP surfaces.
- `SystemErrorResponseFinalizer`, `SystemErrorRecorder`, and `SystemErrorRetention` centralize request references, safe 4xx/5xx rendering, super-admin error reporting, and bounded retention.
- Role controllers are under `app/Http/Controllers/{Admin,Reception,Staff,Customer}`.
- Business invariants are implemented in services including `AppointmentWorkflow`, `AppointmentAvailability`, `AppointmentCompletion`, `TransactionWorkflow`, `AttendanceWorkflow`, `RfmPromotionGenerator`, and `SentimentClassifier`.
- `config/casa.php` owns business hours, pagination, reward presets, and security switches.
- The public landing page displays active `Service` records when available. If none are active, it displays the four `casa.service_packages` as informational reference cards only; fallback packages are never bookable or written to the database.
- Admin Settings stores optional plain-text company history and a role-based Owner → Administrator → Team organizational chart. The landing page exposes one About section and navigation link only after an admin publishes at least one of those content areas; it never derives public chart entries from staff accounts.
- Admin Settings accepts the browser's nested organizational-photo removal payload, preserves existing chart photos across text-only updates, and displays validation failures instead of silently returning to fallback defaults. Reward-settings updates preserve unrelated application-setting defaults when creating the singleton row.
- `tests/Feature` contains the primary behavioral coverage.
- Super-administrator error inbox routes are `admin.system-errors.index`, `admin.system-errors.show`, `admin.system-errors.resolve`, and `admin.system-errors.reopen`; no current business route is intentionally marked unavailable.
- Customer self-bookings create retained database notifications for the assigned therapist and active admins, super admins, and receptionists. Operational users access the inbox at `notifications.index`; View booking checks current appointment access, marks the alert read, and redirects to the recipient's scoped appointment detail page. A missing or reassigned booking is not marked read by a rejected open request.
- Notifications uses a 62/38 list/detail split at 1280px and above, stacking on smaller screens. GET `q` searches retained customer/service/booking-number snapshots, `status=all|unread` filters alerts, and `selected` accepts a recipient-owned UUID on the current 15-record page. Search-aware All/Unread counts span pages; filtering and pagination reset selection. Previewing is read-only and current details/contacts are batch-loaded with therapist assignment guards. Missing/reassigned records retain historical summaries but show no live contacts or notes. Scoped styles live in `resources/css/notifications.css`. View in calendar opens the role's existing appointment index with `calendar_date=YYYY-MM-DD` and `#booking-calendar`; explicit dates initialize the containing Monday-start admin or Sunday-start reception/therapist week and survive browser initialization. Verify with `NotificationsLayoutTest`, `CustomerBookingNotificationTest`, and `tests/js/calendar-week.test.mjs`.
- Operational sidebars show an unread customer-booking count refreshed through authenticated HTTP polling every 30 seconds while visible on their Appointments/My appointments link. The browser reconciles through `notifications.bookings.count`, acknowledges displayed appointment pages through `notifications.bookings.read`, and retains the separate inbox without a badge.
- All roles share a collapsible desktop sidebar: 256px expanded or an 80px icon rail at 1024px and above. `resources/js/sidebar.js` owns the Alpine state and hover/focus labels; the app layout restores `casa.sidebar.collapsed` from localStorage before rendering. Mobile drawers and the customer dock remain independent.
- Role navigation is defined in `resources/views/layouts/navigation.blade.php`: admins have direct Therapists, Services, Customer rewards, Feedback, and Reports links; all roles use task-based group labels and plain-English destinations. The mobile drawer shares those links, and the customer dock uses My appointments, My feedback, and My profile.
